## Done

1. **T1 — href escaping computed in Go.** Every URL the server emits for a
   chain or an attached file is built with `url.PathEscape` per segment, which
   fixes the shipped defect `clarifications.md` names (`html/template`'s URL
   normalizer leaves `#` and `?` unescaped in an `href` path, so a file called
   `a#b.md` was unreachable from the panel). Tests cover `#` and `?`.
2. **T2 — chain value and kind registry.** `internal/web/chain.go`: parse a
   path into an ordered `Chain` of `type/ref` pairs, canonical `Path()`,
   append, truncate, `TaskAt`. `ParseChain` reads `r.URL.EscapedPath()` (not
   `PathValue`, which is decoded, so one `%2F` in a file name could otherwise
   forge a segment boundary), takes the tail by segment index rather than by
   searching for `"/w/"` (a task whose id is `w` would make the first match the
   wrong one), validates every ref through `task.ValidateNameSegment` and caps
   depth at `maxChainDepth` (16). `internal/web/kinds.go`: one registry entry
   per kind declares tag, width class, rail label, fragment and ref resolution;
   `t` and `f` ship.
3. **T3 — `/tasks/{id}` is board + panel.** The standalone `max-w-3xl` detail
   page and `detail.html` are gone; `board.html` is the only page template and
   is always fed a `WorkspaceView`. The pre-existing panel tests moved onto the
   new surface unchanged.
4. **T4 — chain routes, rail and strip shell.** `GET /tasks/{id}/w/{rest...}`
   serves a chain as a page, `GET /strip/{rest...}` the same state as the
   `#strip` fragment. One pattern per family (registering `GET /tasks/{id}/w/`
   beside the wildcard panics). Any malformed chain, unknown kind, missing task
   or missing file is one 404. The nesting rail lives outside the stage, each
   rung linking to the chain truncated to it.
5. **T5 — CSS and the one regeneration.** `.stage` / `.strip` / `.kind-*` /
   `.rail`, the working-column entrance, the project's first
   `prefers-reduced-motion` block and the below-`lg` stack, with `app.css`
   regenerated by `scripts/build-css.sh` in its own commit boundary so the
   generated diff hides no logic.
   - Follow-up within the same phase (`edafac0` plus this phase's final
     commit): every column is one screen tall and scrolls inside itself, and
     the board unit goes one level further — its pane clips (`.pane-board`),

## Deviation from `design.md`

The ADR (`design.md`, Decision) specifies the strip as a flex row with
`justify-content: flex-end` — columns right-aligned at any depth, what runs off
the left clipped. What shipped is **left-aligned** (`justify-start`) with a
single `translateX` step: opening anything slides the board off the left, the
root task's own column takes its leftmost slot, and free space may remain on
the right. Because exactly one unit ever leaves, the offset is one width
(the board's) rather than a sum over the kinds scrolled past, so one custom
property carries it and Go only says whether the board is away
(`strip-shifted`), never how many pixels.

Everything the ADR's consequences hang on is unchanged: no geometry in Go, no
`style` attribute, `overflow-x: clip` on the stage, the rail outside it, and
nothing to restore after an htmx history replay. CLAUDE.md documents the
shipped rule; this file is the record that `design.md` is the earlier intent.

The ADR's named fallback (uniform column width plus a bounded `.step-N` set)
was **not** triggered — see T7.

## T7 — manual browser pass

Walked a chain to depth 5 in the browser at desktop width and below `lg`.
Result: **pass**, no fault found, the ADR's animation fallback not triggered.
Checked:

- opening a column slides the board off the left by exactly one board width;
  the strip is left-aligned and free space may remain on the right;
- the slide runs as a keyframe animation (`strip-slide`, 260 ms) on insertion,
  which is the only form that can work — htmx replaces the whole `#strip` and a
  freshly inserted element has no previous value to transition from. Older
  columns reflow instantly while the working column slides in; this reads
  correctly, so the ADR's uniform-width + `.step-N` fallback stays unused;
- no horizontal scrollbar in any state, and the strip cannot be panned with a
  wheel or trackpad (structural: `overflow-x: clip` is not a scroll container);
- the rail stays pinned as columns leave off the left;
- every column is one screen tall and scrolls inside itself, the page itself
  never scrolls, the board's status columns scroll independently, and all
  scroll offsets survive the five-second poll;
- browser Back steps the chain back one column and a deep-link reload
  reproduces the layout (every state is a real URL; no layout state in JS);
- below `lg` the strip stacks, the panes and column bodies grow to their
  content and the page scrolls normally.
