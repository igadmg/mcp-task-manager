Fix task ID allocation so `create_task` chooses an ID greater than every active or archived task ID.

Currently `Index.NextID()` only considers active index entries. After all active tasks were archived, a new task was incorrectly created as ID 1 even though archived tasks already used IDs through 78. This can reuse IDs and create ambiguous active/archive lookups.

Update the ID-allocation path to account for `tasks/archive/*.md` as well as active tasks while preserving the archive's no-index design. Review both `internal/storage/index.go` and `internal/storage/markdown.go` so all ID-allocation APIs have consistent semantics. Add regression tests covering an empty active set with archived tasks and a mixed active/archive set, including the case where the highest ID is archived.

Acceptance criteria:
- New task IDs are one greater than the maximum ID across active and archived tasks.
- Archived IDs are never reused.
- Existing ordering and archive lookup behavior are unchanged.
- Focused storage and task-service tests pass.
