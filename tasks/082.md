Add the workflow controller rules for non-writing phase mutation detection, coder/reviewer iteration, real dispatch failure handling, and capability-based model/reasoning recommendations.

Files:
- Modify: `skills/superpowers-workflow/SKILL.md`
- Reference: `docs/plans/2026-07-10-implicit-subagent-roles-migration.md`

Steps:
1. In the planning phase, add explicit controller instructions to record the worktree state before dispatching the planner and compare it after the planner returns.
2. State that unexpected planner file changes must stop the workflow and be reported to the user; the controller must not silently revert them.
3. In the reviewer phase, add the same pre/post worktree-state comparison for review dispatches.
4. State that unexpected reviewer file changes must stop the workflow and be reported to the user; the controller must not silently revert them.
5. Replace obsolete role-agent-unavailable error handling with handling for real dispatch failures, unavailable task-manager/tools, missing task context, and returned role result states such as `NEEDS_CONTEXT` and `BLOCKED`.
6. Update review iteration behavior so findings are sent back to the same coder subagent when possible.
7. The coder follow-up message must repeat the material scope and ownership constraints instead of relying on the role name alone: task ID/title, issue findings, edit-only-needed-files rule, no task-manager mutation, no commits, no unrelated cleanup, and required result vocabulary.
8. Add the capability-based model/reasoning policy: inspect the active `spawn_agent` schema at every role dispatch; if no model/reasoning controls exist, omit them and continue with runtime defaults; if controls exist, pass only supported fields and values.
9. Document recommended defaults as guidance only: planner `gpt-5.6-sol` with reasoning `medium` and higher effort for complex planning; coder `gpt-5.6-terra` with reasoning `xhigh`; reviewer `gpt-5.6-terra` with reasoning `xhigh`.
10. Explicitly state that user choices, availability, policy, cost/latency constraints, and task-specific needs may override all recommendations, and role correctness comes from the prompt rather than model selection.

Code guidance:
- Keep mutation detection as workflow instructions using `git status`/diff inspection language; do not invent a new code API.
- Be precise that lack of model controls is normal for the current schema and not a fallback or error.
- Do not reintroduce custom-agent fallback language while adding dispatch failure handling.
- Preserve existing task lifecycle behavior: start before work, complete after accepted work, commit by controller only.
